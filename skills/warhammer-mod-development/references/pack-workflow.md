# 源文件与 Pack 工作流

## 前提

- 本地源文件是唯一修改入口；先读取当前文件，保留已有无关改动。源与 Pack 不一致时按源重新导入。
- Agent 不直接或间接启动、重启游戏。静态检查、离线测试、Pack 检查和现有日志分析由 Agent 执行；游戏操作由用户完成。
- 从目标项目的 `pack_map.json` 取得 MOD 源目录与源 Pack。缺映射时先确定候选并补全记录，只有路径尚未获授权或无法确定时才请用户确认；不得猜测目标后写入。
- 只写映射的源 Pack。原版和第三方依赖是只读基准；文档/技能本身的修改无需导入游戏 Pack。

## RPFM MCP

1. 检查本机 RPFM MCP（项目常用 `http://127.0.0.1:45127/mcp`）。未启动时查找本机 `rpfm_server.exe` 并以隐藏窗口启动，等待端口就绪；失败则报告。MCP 不可用时才使用本机 `rpfm_cli --help` 确认的同等功能。
2. `set_game_selected` 选择 `warhammer_3` 并加载 schema / dependencies；出现 `There is no Schema for the Game Selected.` 时先修复此步骤。没有依赖缓存的扫描不能证明引用正确。
3. `list_open_packs` 检查已有目标会话，存在则复用 `pack_key`；否则打开映射目标。每次写入只选一个目标会话。需要原版诊断依赖时，先打开目标，再用单独调用打开原版，不能合并成待保存目标。
4. 仅导入本次修改路径：DB / LOC TSV 用 `import_tsv` 转为游戏二进制；Lua / XML / PNG / DDS / RMV2 等用 `add_packed_files`。不要在 Pack 留裸 `.tsv`。
5. 保存前再次 `list_open_packs` 核对 `pack_key` 的绝对路径，`open_pack_info` 核对条目集合。发现原版路径、异常资源数量或意外条目时，关闭涉及会话且不保存，重新建立明确的目标会话。
6. `save_packfile` 保存同一映射源 Pack；重新读取修改条目。DB 比较行数、键和改动字段，二进制资源比较 SHA-256。
7. 对目标运行 `diagnostics_check`。处理真实 Error：回到源修复，再导入、保存、读回、复扫。Warning 单独记录，不为清警告扩大任务。已确认的外部依赖误报（如 `cr_combi_expanded`）记录依据，不向补丁复制原版 DB/UI/模型，也不伪改引用。

诊断工具失败、未识别结果或缺依赖时明确写“诊断未完成”，不能把它当成 0 Error。已有占用导致拒绝保存时先确认占用者和会话，不杀进程、不绕过映射另存；继续完成能做的源检查。

## 污染 Pack 恢复

确证污染后，以补丁源目录重建临时 Pack，只导入该目录的实际内容。确认内部条目集合与源逐项一致，备份污染的映射 Pack，再替换到原映射路径。保留污染备份。这是恢复流程的例外，不作为正常增量导入方式。

## 交付证据

给出修改源文件、映射 Pack、导入内部路径、读回结果、Error/Warning 或诊断未完成原因。游戏效果只能依据用户复测或现有相关日志报告，离线检查不等于游戏测试。
