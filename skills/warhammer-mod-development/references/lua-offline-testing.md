# WH3 Lua 离线回归

用于状态机、技能队列、结算、事件/定时器、存档和 Lua UI 生命周期的行为验证。优先复用项目现有测试环境；纯 DB 或简单展示改动按其数据、资源与格式检查验收，不统一要求建立 mock 框架。

## 选择运行环境与执行路径

- 用 Lua 5.1 运行实际 MOD 源文件。可以使用本机 Lua 5.1，或 Python 的 `from lupa import lua51`；核对实际运行版本，避免默认 `lupa.LuaRuntime` 选到其他 Lua 版本。`luac -p` 只检查语法。
- 测试驱动真实加载、初始化和事件路径，按原版加载器或模块调用者确定入口；不要把“所有 Lua 文件都有同名全局入口”当成通用规则。
- 将 `cm`、`core`、UI、CCO、文件系统与内存边界集中在测试环境中，角色、技能树、事件 context 等业务数据放进 fixture。每个独立场景创建隔离环境，连续操作场景在同一环境中跑完整周期。
- 排查 bug 时先用玩家路径复现旧代码的错误，再验证修复。追踪触发 → 状态/记录 → 结算/UI → 保存 → 新会话载入，不用重新实现一份业务逻辑代替加载源码。
- 原生 API 先核对当前原版脚本或文档，再实现替身。涉及字符串搜索时同时执行 [CA 字符串契约](ca-string-api.md)，标准 Lua 的字符串库不代表 WH3 的替换接口。

## 按改动选择场景

以下是候选覆盖，不要求每个 MOD 跑满所有类别；选出的场景必须能区分本次正确行为和实际错误。

| 场景 | 输入与操作 | 关键断言 |
|---|---|---|
| 正常路径 | 数据齐全，按玩家操作顺序执行 | 实际状态、调用参数与结果正确，临时资源按生命周期释放 |
| 边界数据 | nil/null 对象、空集合、零值、最大值、非法记录 | 按业务规则拒绝、过滤或完成，保留合法数据 |
| 延迟与取消 | 数据暂未就绪；回调等待期间关面板、换角色或取消 | 就绪后只提交一次；过期回调不访问旧对象、不写错角色 |
| 连续操作 | 关闭再开、第二场、重复事件或重复初始化 | 不残留前一轮状态，不重复监听、扣点、发奖或提交 |
| 旧状态与残留 | 旧存档、重建对象；内存 hook 场景另加补丁残留 | 迁移与身份绑定正确；需要原始字节时确实走已核实的穿透路径 |
| 永远无法就绪 | 持续无效数据、提交永无变化、对象永久失效 | 在业务规定的次数或时间边界停止，后续驱动不会无条件重启 |
| 保存恢复 | 保存后修改运行状态，再在新环境中载入保存快照 | 恢复保存时的值，持久化字段完整；会话状态按设计重新建立 |

每个场景结束时还检查本流程的临时监听器、定时器、待执行回调和 hook。预期长期保留的监听器按契约核对，不能为“零残留”删除正常长期功能。

## 断言与失败汇总

优先断言业务状态、引擎边界调用记录、队列内容、保存数据和资源注册表。日志用于定位执行边界，不能用日志包含“完成”代替实际扣点、结算或保存值断言。

统一汇总加载、入口、事件条件、回调和定时器异常，以及未知 API、非法参数和其他契约违规。违规在替身入口独立记录，即使待测代码用 `pcall` 吞掉错误，用例结束仍须失败。日志错误检测按模块实际格式补充，不固定成只搜索 `!!` 或“回调异常”。

未知调用检测须覆盖测试中注入的所有边界，包括 `cm`、`core`、UI、CCO 与 memreader。业务有意探测可选 API 时，在该 fixture 中明确提供“存在/缺失”条件和预期降级行为；不把缺失桩悄悄当作成功、nil 或通用无操作。

本次相关回归失败时，先区分源码错误、替身错误、fixture 错误和环境问题，再修正重跑。保留与本次无关的基准失败及其证据。测试进程有失败或未捕获异常时返回非零退出码，并核对预期用例/检查数量，避免把中途停止或泛泛的 PASS 当作完成。

## 复用框架前先校准契约

框架演示通过只证明演示场景。采用或修改公共替身时，用最小独立用例校准下面的相关能力；业务改动只重跑它涉及的框架与场景。

| 能力 | 必须保留的语义与可检查结果 |
|---|---|
| `core:add_listener` | 同一事件可有多个不同名称的监听器；条件函数或固定 `true`；第四参数必须是回调函数；`persistent=false` 在首次执行回调后移除 |
| `core:remove_listener` | 按监听器名称删除；删除 A 后，同事件的 B 仍能执行。初始化重复注册和回调内删除按原版实现核对 |
| 延迟/重复回调 | 保留目标 API 的时间单位、到期与取消语义。需要测顺序、超时或取消时用可推进的虚拟时钟；立即排空队列只用于不依赖这些行为的冒烟 |
| 存档 | 保存序列化快照或可独立复制的数据，而非运行中 Lua 表的引用；保存值为 1、随后改为 2，新环境载入仍为 1 |
| 模块加载 | 当前 Lua 5.1 下能加载实际模块；字符串源码用 `loadstring`，`load` 接收 reader 函数 |
| 严格错误记录 | 给每种边界注入一次未知调用和非法参数；用 `pcall` 捕获后，失败汇总仍能识别违规 |

同一 Lua 环境内调用保存/读档回调可测回调逻辑；验证持久化还需要跨新环境恢复，不能共享旧 Lua 表、闭包或 userdata。

## 内存、CCO 与 UI 的专项边界

**假内存**按当前读取器与对应版本的数据结构构造，记录布局来源。覆盖内联/外部字符串、空指针、空 vector、未就绪或读取失败等实际分支；仅对该读取器确实检查对象头的结构设置有效头部。未配置地址可作为明确的零值 fixture，但用来模拟读取错误时须显式注入失败，不能让全零默认值掩盖越界或错误偏移。`eq`、NULL、指针包装和 `read_original` 的语义以当前 memreader 为准；E9 残留场景只用于实际采用该类 hook 的 MOD。

**CCO**记录表达式、目标身份、扣点、等级与提交变化。按本次目标模拟满级、零点、装备锁、前置条件和延迟刷新等相关约束；“记录了 AddPoint 调用”不等于状态已经变化。替身同步刷新内存时，只能断言该模拟节奏下的行为。

**UI**先做入口、事件和回调冒烟，再给相关交互添加状态断言：打开 → 点击 → 延迟回调 → 关闭 → 重开，覆盖目标面板销毁或角色切换后的过期引用。假组件树来自已确认的运行时路径或明确标注的假设，不能把 XML 静态树当真实运行时树；冒烟通过不能证明布局、绑定或实际点击效果。

## Lupa 互操作注意事项

只在使用 Python/Lupa 测试环境时读取本节。

- `obj:m(x)` 的 Lua 语义是 `obj.m(obj, x)`。区分 Lua 表中的 Python 函数、Python 对象的绑定方法和点/冒号调用，用当前 Lupa 版本的小例核对实参；不能根据 Python 函数有没有 `*args` 判断 self 是否传入。
- Python 类方法中访问 `g['__mock_state']` 等 Lua 全局用字符串下标，避免 `g.__mock_state` 被 Python 私有名称改写。Python 侧读取 Lua 表的 `items`、`keys`、`values` 字段也用字符串下标，避免命中包装对象的方法。
- Lua 数组从 1 起；Python list 传入时按所需语义用 `table_from` 转成 Lua 表。Lua 表与 Python list 不直接比较，按索引转换或逐项断言。
- 单个 Lua 表返回值仍是表；`a, b = lua_fn()` 可能遍历表的键。真正多返回值按实际返回对象取值。`unpack_returned_tuples` 控制 Python tuple 返回到 Lua 时是否展开，不会把 Lua 表自动变成多返回值。
- `L.eval` 用于表达式，语句用 `L.execute`。二进制 Lua 字符串跨 Python 边界时显式选择 bytes/编码策略，文本日志另行解码，避免默认 UTF-8 解码掩盖原始字节问题。

## 交付证据

报告实际 Lua/框架版本、运行命令、相关场景、预期数量、通过/失败/异常和未覆盖行为。离线通过后，MOD 源码交付继续按项目的源 Pack 导入、保存、回读与 Error 诊断规则执行。

离线模拟验证的是所覆盖的代码路径与替身契约；真实 API 实现、内存偏移、引擎事件顺序、UI 重建、原生崩溃和性能仍需对应源码、日志或用户游戏实测证据。Agent 不启动游戏；给用户具体复测动作，分别报告离线、Pack 与游戏结果。
