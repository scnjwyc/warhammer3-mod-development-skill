# 战锤3 MOD 本地化翻译规范

本技能专门处理 MOD 本地化文本（`.tsv`/`.loc`）的**翻译写入**与**已有译文的术语校对**。
DB 表结构、Lua 脚本、技能图标绘制等其它 MOD 开发内容，参见 `warhammer-mod-development` 技能。

## 关键路径（翻译时必用）

| 用途 | 路径 |
|------|------|
| 术语库（先查这里） | `多语言/术语库.md`（工作区共享，所有 skill 引用同一份） |
| 英文原版本地化（搜英文术语） | `多语言/EN/` |
| 中文原版本地化（用 key 查官方译名） | `多语言/localisation__.loc_CN.tsv` |
| MOD 文本输出目录 | `mod/[MOD名]/text/db/` |

## 本地化键名命名规范

游戏从本地化文件加载文本时，键名必须遵循固定命名规范，由**表前缀** + **完整键名**组成。

**格式**：`{表前缀}_{完整键名}`

一个键通常对应两个本地化键：标题和描述。查询原版本地化文件获取用法示例。
例如，effects_tables 的键使用前缀 `effects_description_`。

### 常见错误

**错误**：直接将完整键名用作本地化键。

```tsv
-- 错误！游戏查找的键不是这个
wyccc_ogre_feast_warning_debuff	饕餮预警	debuff.png
```

**正确**：使用表前缀 + `_localised_title_` / `_localised_description_` 前缀。

```tsv
-- 正确！游戏查找这两个键
effect_bundles_localised_title_wyccc_ogre_feast_warning_debuff	饕餮预警
effect_bundles_localised_description_wyccc_ogre_feast_warning_debuff	食人魔大军逼近，城镇秩序下降，防御力量被削弱。
```

## 翻译规则（写入本地化文本时必须遵守）

### 1. 换行符必须使用字面的 `\n`（两个字符：反斜杠 + n）

**本地化文本中的换行，统一用字面字符串 `\n` 表示——即文件里实实在在写着反斜杠 `\` 和字母 `n` 这两个字符。**

这是本技能最容易写错的一条，务必区分三种"换行"：

| 写法 | 是什么 | 能否使用 |
|------|--------|---------|
| `\n`（字面反斜杠 + n，两个 ASCII 字符） | 文件里的明文两个字符，游戏解析后渲染成换行 | ✅ **唯一正确的写法** |
| 真正的换行控制符（LF / `\n` 转义码） | 文件里真的断了一行 | ❌ 禁止，会破坏 TSV 结构 |
| 物理换行（在源码里按回车把文本写成多行） | 文件里真的多了一行 | ❌ 禁止 |

**写入文件时，`text` 列必须保持单行，内部用字面 `\n` 两个字符表示换行。** 当用 Write/Edit 工具写入时，要写入的是字面反斜杠和 n（即字符串里是 `\\n`，落盘后看到 `\n`），不要写成真实换行。

例如描述中需要分段时：

```tsv
-- ✅ 正确：用字面 \n（反斜杠 + n），整条记录物理上是一行
effect_bundles_localised_description_xxx	第一段内容。\n第二段内容。\n第三段内容。

-- ❌ 错误：物理换行（文件里真的断行）
effect_bundles_localised_description_xxx	第一段内容。
第二段内容。
```

**自检**：写入后用 `grep -c` 或编辑器确认——同一条 TSV 记录的行数必须为 1；如果 `text` 列把内容拆到了下一行，就是写错了。

### 2. 术语必须查原版翻译库，禁止机翻

**所有人名、地名、物品、单位名称、法术等专有术语，均需查询原版翻译库获取标准译名，不得机翻。** 宁可不翻译（保留原文），也不要机翻。

本技能的翻译流程严格分为两个阶段：**阶段一 术语预处理**（提取 + 查库 + 替换），**阶段二 句子翻译**。禁止跳过阶段一直接翻译句子——句子级翻译时人脑/模型最容易对专有名词"凭语感顺手翻"。

#### 阶段一·步骤 1：提取所有术语（强制第一步，最优先）

**拿到待译文本后，第一件事是逐句扫一遍，把所有专有术语挑出来，列成清单——不要直接动手翻译句子。**

需要提取的术语类型：

| 类型 | 示例 |
|------|------|
| 人名 / 角色名 / 别称 | `Grimgor`、`Zhao Ming`、`The Heavenly Bowman` |
| 地名 / 区域 / 城市 / 要塞 | `Nan-Gau`、`Wei-Jin`、`Great Bastion`、`Mountains of Heaven` |
| 物品 / 武器 / 装备名 | `Gitsnik`、`Blades of Shang-Yang`、`Banner of Feng Shi` |
| 单位 / 兵种名 | `Celestial Dragon Guard`、`Jade Warriors`、`Bloodletter` |
| 种族 / 派系 / 势力名 | `Dawi-Zharr`、`Beastmen`、`Cult of the Exquisite Cadaver` |
| 法术 / 技能 / 机制名 | `Waaagh!`、`Feng Shi Sorcery`、`Harmony` |

- 提取时**宁多勿漏**：拿不准是不是术语的词（如 `crane`、`jade` 这种在此处可能构成专有名词的普通词）也先列进去，留到查库时确认。
- 提取出的术语清单先列在本轮对话里（或 TodoWrite 记录），作为后续逐项查证的工作清单。

#### 阶段一·步骤 2：对照术语库替换（模糊匹配，命中即替换）

路径：`多语言/术语库.md`（工作区根目录下的共享术语库，所有 `warhammer-mod-translation` 技能副本——`.zcode`/`.codex`/`.cursor`——都引用这同一份文件，改一处即全局生效）

术语库收录了此前翻译中**已按原版库验证过**的标准译名，命中则直接复用，禁止自行另译。

**用模糊匹配的方式查术语库，不要只做精确等值匹配。** 具体要求：

- **忽略大小写**：术语库写的是 `Grimgor`，文本里出现 `grimgor`、`GRIMGOR` 也要命中。
- **忽略复数 / 词尾变化**：术语库写的是 `Bloodletter`，文本里的 `Bloodletters` 要命中；`Jade Warrior` 对 `Jade Warriors`、`Skink` 对 `Skinks`、`Greatsword` 对 `Greatswords` 同理。
- **容忍定冠词 / 连字符 / 空格差异**：`The Heavenly Bowman` ↔ `Heavenly Bowman`，`Nan-Gau` ↔ `Nan Gau`，`Dawi-Zharr` ↔ `Dawi Zharr` 都应视为同一术语。
- **子串也要查**：术语库里的多词术语（如 `Celestial Dragon Guard`）可能是更长词组的一部分，反过来也要注意短术语嵌在长词组里的情况。

实操建议：用 Grep 在术语库文件里按**小写词干**搜索（如 `grep -i "grimgor"`、`grep -i "bloodletter"`），逐个术语核对其译名行；不要把多个术语拼在一个正则里批量搜（会漏命中且丢失对应关系，见反面案例 1）。

**步骤 2 的产出**：一份「英文术语 → 标准译名」映射表，所有术语库命中的条目直接定译；未命中的留待步骤 3 查原版库。

#### 阶段一·步骤 3：术语库未收录的术语，查原版库（EN → key → CN）

对步骤 2 未命中的术语，逐个走原版库查证：

**步骤 3a：用英文名词在英文库搜索**

路径：`多语言/EN`

- 用 Grep 在 `EN` 目录下搜索该术语的英文原文（如 `Grimgor`、`Celestial Dragon Guard`、`Comet of Casandora`）。
- 搜索结果大概率命中一整段英文文本（词条是完整的句子或段落），而不是孤立的单词。
- 从这段英文文本中确认该术语确实存在，并定位其所在的行/条目。
- **每个术语独立搜索，不要把多个术语拼在一个正则里批量搜**——批量搜会漏命中，且无法对应到具体 key（详见下方反面案例）。

**步骤 3b：用 key 去中文库查翻译**

路径：`多语言/localisation__.loc_CN.tsv`

- 英文库每条记录都有一个 `key`（通常是第一列），用这个 `key` 在中文库中查找对应行。
- 从中文翻译文本中提取该术语在官方中文版里的标准译名（如 `Grimgor` → `格里姆格`）。
- 该译名即为写入本地化文件时应使用的标准译名。

**步骤 3c（强制）：回填术语库**

每从原版库确证一个术语库尚未收录的新术语，**立即追加到 `多语言/术语库.md` 对应分类下**（英文 / 中文 / 出处 key 三列）。术语库需随翻译工作持续增长，这是翻译流程的强制环节，不是可选项。

#### 阶段一·步骤 4：备选——联网查询

**如果原版翻译库中查不到该术语**（例如是新加入的内容、或是非官方术语），再联网查询标准译名：
- 优先查战锤官方维基、战锤中文社区等权威来源
- 仍查不到时，**保留英文原文，不要机翻**——宁可整段留英文，也不要给出低质量机翻

#### 阶段二：句子翻译

**术语映射表完整后，才开始翻译整句。** 翻译时把句子中的英文术语直接替换为映射表里的标准译名，普通英文词（非术语）正常翻译成中文。术语库中已有的译名不得擅自替换为"更顺口"的写法；若发现译名与原版本地化库不一致，以原版本地化库为准并修正术语库。

#### 流程示意

```
待译文本 "...The Celestial Dragon Guard defend Nan-Gau..."
    │
    ▼ 阶段一·步骤 1：提取术语清单
[Celestial Dragon Guard, Nan-Gau, ...]
    │
    ▼ 阶段一·步骤 2：模糊匹配 多语言/术语库.md
    ├─ Celestial Dragon Guard → 命中"天廷龙卫" ✅
    └─ Nan-Gau → 命中"南皋" ✅
    （全部命中，无需查原版库）
    │
    ▼ 若步骤 2 未命中 ↓
    ▼ 阶段一·步骤 3a：Grep 搜索 多语言/EN（单独搜，不要批量）
命中 key = "wh3_main_unit_description_cth_celestial_dragon_guard"
对应的英文段落："...The Celestial Dragon Guard are..."
    │
    ▼ 阶段一·步骤 3b：用该 key 查 多语言/localisation__.loc_CN.tsv
命中中文段落："...龙卫军是..."
    │
    ▼ 提取译名 → 标准译名 = "龙卫军"
    │
    ▼ 阶段一·步骤 3c（强制）：把 {英文, 中文, 出处 key} 回填进 多语言/术语库.md
    │
    ▼ 阶段二：句子翻译（用术语映射表替换后通顺成句）
"...天廷龙卫守卫南皋..."
```

#### 禁止事项

- ❌ 跳过术语提取直接翻译句子（最容易凭语感翻错）
- ❌ 查术语库只用精确匹配，忽略大小写/复数导致漏命中
- ❌ 直接用翻译工具（机翻）翻译专有名词
- ❌ 想当然地自行音译或意译术语
- ❌ 混用不同译名（同一术语在不同条目中译法不一致）
- ❌ 翻译前不查术语库就直接动手
- ❌ 查证了新术语却不回填术语库（让下一次翻译重复踩坑）
- ❌ 把多个术语拼在一个正则里批量搜（会漏命中且丢失 key 对应关系）
- ❌ 译文中夹带未经查证的英文单词（如把 `gibbering`、`razor`、`hamstring`、`crews`、`celest` 这类普通英文词原样留在中文译文里）

### 反面案例（真实踩坑记录，务必引以为戒）

以下是一次 legend lore 汉化中真实犯下的错误，已被用户指出并修正。每条都对应上方某条禁止事项，**不要再犯同样的错**。

**案例 1：批量正则搜索导致漏查术语**

把多个术语拼在同一个 Grep 正则里搜：
```
Grep pattern: "Iron Dragon|Jade Dragon|Heavenly Bow|Tiger Court|..."
```
结果只命中了一两个（如 `Heaven's Gate`），就草草判定"已查证"。
- **实际后果**：`Iron Dragon`、`Dawi-Zharr`、`Tiger Court`、`House of Secrets` 等关键术语全部漏查。
- **正确做法**：每个术语单独搜索，逐个走完"EN 库搜英文 → 取 key → 中文库查译名"的完整流程。

**案例 2：跳过"步骤 3b（用 key 查中文库）"凭印象改译**

`Iron Dragon` 在 Grep 结果中没有直接命中带上下文的段落，于是**跳过了"用 key 查中文库"这一步**，凭印象译成"铸铁龙"。
- **实际后果**：原版标准译名是**镔龙**（出处 `ancillaries_colour_text_wh3_cp1_anc_weapon_blades_of_shang_yang`："这套华丽的拳刃乃是奉镔龙本人之命…"）。"铸铁龙"是完全错误的译名。
- **正确做法**：EN 库搜到 `Iron Dragon` 后，取该条 key，到 `localisation__.loc_CN.tsv` 查同 key，从中文段落中提取标准译名。

**案例 3：术语直接保留英文不翻译**

`Dawi-Zharr` 在译文中原样保留英文，没有查证。
- **实际后果**：原版标准译名是**扎尔矮人**（出处 `ancillaries_colour_text_wh3_dlc23_anc_armour_blackshard_armour`）。保留英文属于漏翻。
- **正确做法**：所有英文专有名词都要查证，查不到才保留原文并标注"待查"。

**案例 4：把概念词当作"诗化标题"擅自改名**

`Heavenly Bowman` 是祟唐在原版库中的固定别称（标准译名**天穹射手**），却自作主张译成"苍天弓神"当作章节标题。
- **实际后果**：与游戏内术语脱节，玩家无法对应。
- **正确做法**：原版已有的固定别称/称号，必须采用原版译名，不得为了"听起来更诗意"而改写。即便用作章节标题也应统一。

**案例 5：译文夹带未查证的英文普通词**

译文中出现了 `gibbering 的恶魔`、`razor 锋利的爪刃`、`hamstring 了一头`、`炮兵 crews`、`在 celest 的鏖战中` 等中英混杂写法。
- **实际后果**：这些是普通英文词（非专有名词），本应译成中文，却因为翻译时图省事直接保留。
- **正确做法**：译文中除原版保留的专有英文（如 `Waaagh!`、武器原名 `Gitsnik`）外，不允许出现未翻译的英文单词。翻译完成后必须做一次全文扫描（可用脚本检测 text 列中长度 ≥ 4 的英文单词）。

**案例 6：武器名括注错误**

`Gitsnik`（格里姆格的战斧）首次出现时括注为"（碎颅者）"。
- **实际后果**：原版标准译名是**灭人斧**（出处 `ancillaries_onscreen_name_wh_main_anc_weapon_gitsnik`）。"碎颅者"是凭印象编的。
- **正确做法**：武器/物品名同样要走查证流程。

## 校对已翻译文本中的术语（第三方/旧翻译校正）

对**已有中文译文**的条目进行术语校对时，不能直接拿中文词去原版库搜——中文词
本身可能就是错的。必须采用"中文→英文→标准流程"的绕回查证法：

### 校对流程

```
已有中文条目中的疑似译名（如"提尔赛斯"）
    │
    ▼ 步骤 A：找到该条目对应的英文原文
    ├─ 有英文源文件（mod/xxx/english/text/）→ 直接按 key 匹配
    ├─ 无英文源文件 → 从条目 key 名反推英文关键词
    │
    ▼ 步骤 B：从英文原文中提取该专有名词的准确英文拼写
    ├─ "提尔赛斯" → 对应 EN 文本中的 "Tirsyth"
    │
    ▼ 步骤 C：用该英文术语走标准翻译查询流程（阶段一）
    ├─ 步骤 2：模糊匹配查 多语言/术语库.md → 命中则直接复用
    ├─ 步骤 3a：在 多语言/EN 目录下搜 "Tirsyth" → 找到 key
    ├─ 步骤 3b：用 key 在 多语言/localisation__.loc_CN.tsv 查官方译名 → "提西茨"
    │
    ▼ 步骤 D：对比官方译名与 mod 中文译文
    ├─ 一致 → 通过
    └─ 不一致 → 替换为官方译名（"提尔赛斯" → "提西茨"）
```

### 反面案例

**`提尔赛斯——灰烬厅`**：
- 中文文本看起来通顺（一个音译地名 + 意译描述），不对比英文无法发现错误
- 英文原文为 `Tirsyth`（key: `wh_dlc05_wef_tree_tirsyth`）
- 官方 CN 译名为 **提西茨**
- `提尔赛斯` 是旧译者凭音感自创的译名，与原版不符

**教训**：**不能凭中文语感判断译文是否正确。** 必须找到英文原名，再走标准查证流程。

### 批量校对策略

1. 从 mod 英文源文件中提取所有大写专有名词（地名/人名/物品名/单位名等）
2. 对每个英文专有名词，走标准流程查官方 CN 译名
3. 在 mod 的中文文件中搜索官方 CN 译名是否存在
4. 不存在 → 该条目用了错误译名 → 找出用了什么、替换为官方译名
5. 存在 → 候选通过（但仍需人工抽检，防止同词异译恰好撞上）

## 翻译完成后自检清单

- [ ] 所有本地化键名遵循「表前缀 + 完整键名」规范
- [ ] 换行符全部使用字面 `\n`（反斜杠 + n 两个字符），无物理换行、无真实换行控制符
